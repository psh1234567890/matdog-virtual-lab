# MATDOG Virtual Lab

**국립중앙과학관 원데이 AI 클래스 체험을 확장한 3D 가상 로봇 제어 실험실**

> **주의:** 교육용 시뮬레이터입니다. 실제 MATDOG 하드웨어와 통신하지 않으며 3D 모델은 실물 정밀 복제가 아닙니다. 신호등 입력은 버튼으로 선택하며, 밝기는 가상 센서값입니다. 결과를 실제 로봇의 인식 정확도로 해석하면 안 됩니다.

## 배경 및 탐구 질문

원데이 AI 클래스에서 Claude로 사족보행 로봇의 제어 웹앱을 제작하고, 밝기 센서에 따른 자동 조명과 카메라의 신호등 색상 판별에 따른 이동·정지를 체험했다. 실제 로봇 없이 제어 원리를 후속 탐구하기 위해 Three.js로 가상 실험실을 만들었다.

**질문:** 센서값이 기준값 근처에서 반복적으로 변할 때, 히스테리시스 제어가 불필요한 조명 전환을 줄일 수 있을까?

### 제어 방식

| 방식 | ON 조건 | OFF 조건 | 그 외 |
|---|---|---|---|
| 단일 임계값 | 밝기 < 30 | 밝기 >= 30 | 없음 |
| 히스테리시스 | 밝기 < 30 | 밝기 > 40 | 기존 상태 유지 |

## 핵심 기능

- 기본 도형으로 만든 3D 사족보행 로봇과 다리 애니메이션
- 카메라 회전 및 확대, 신호등 모의 입력
- 가상 밝기 센서 슬라이더와 전면 조명
- 실시간 제어 방식 선택
- 동일 밝기 시퀀스·초기 OFF 상태에서 두 방식 비교
- 조명 전환 횟수, 변화 그래프, 결과표, CSV 다운로드
- 반응형 화면과 발표용 전체 화면 모드

## 실행 및 빌드

Node.js 22 이상 권장. 최초 npm 설치 시 인터넷 접속이 필요하다.

    npm install
    npm run dev

테스트 및 프로덕션 빌드:

    npm test
    npm run build
    npm run preview

## 실험 재현 방법

1. 실험 조건(임계값 근처의 흔들림 / 점차 변화 / 넓은 범위의 잡음)을 선택한다.
2. 비교 실험 실행을 누른다.
3. 두 방식의 조명 상태와 ON↔OFF 전환 횟수를 비교한다.
4. 동일 실험을 재실행해 출력이 같은지 확인한다.
5. CSV로 단계별 센서값과 상태를 저장할 수 있다.

**통제 조건:** 초기 조명 OFF, 동일한 입력 시퀀스, 동일한 관측 단계.

**측정 지표:** 조명 상태 전환 횟수(초기 OFF에서 첫 ON으로 바뀌는 순간도 포함). 전환 감소율은 단일 방식 대비 전환 횟수의 감소 비율이며, 실제 측정한 전력 소모나 카메라 인식 정확도가 아니다.

**한계:** 가상 센서 입력만 비교한다. 히스테리시스는 전환 횟수를 줄일 수 있지만 조건에 따라 조명 OFF 반응이 늦어질 수 있다. 실물 로봇의 센서 오차, 네트워크 지연, 물리적 응답을 검증하지 않았다.

## 자동 테스트

Node.js 내장 테스트 러너로 경계값(30, 40), 이전 상태 유지, 전환 횟수, 재현성, 잘못된 입력, 신호등 제어, CSV 생성 여부를 검사한다.

Settings → Pages → Build and deployment → **GitHub Actions** 선택. main 브랜치 푸시 시 테스트·빌드·배포가 실행된다.

## 생성형 AI 사용 범위

이 프로젝트는 학생이 체험한 내용을 바탕으로 AI와 협업하여 제작하는 후속 탐구용 프로그램이다. 학생이 전체 코드를 직접 작성했다고 주장하지 않는다.

- **학생 경험·방향 결정:** 실제 MATDOG 체험과 밝기·카메라 제어 기능 설명, Three.js 사용 및 GitHub 공개 결정
- **AI 보조:** 시뮬레이터 구조, UI·코드, 테스트, 배포 설정 작성
- **검증 증거:** 소스 코드, 단위 테스트, Actions 로그, 가상 센서 입력과 CSV
- **학생의 직접 실험 및 해석:** 발표와 보고서에는 실제로 수행하고 이해한 부분만 기재

실제 체험 결과, 가상 프로그램 구현, 새로 실행한 실험 결과는 반드시 구분한다.
